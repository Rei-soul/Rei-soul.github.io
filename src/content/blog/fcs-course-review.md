## 为什么这门课值得用力学

大一写代码时，程序对我来说是一个黑盒：源文件进去，可执行文件出来。FCS（计算机系统基础）这门课做的事情就是把这个盒子拆开——从一段 C 代码如何变成汇编、如何被链接器拼接，到运行时数据如何在存储器层次间流动。

> 学完之后再回头看 C 语言的指针、内存泄漏、缓存友好代码，会有一种"终于看清地形"的踏实感。

## 学习路线

按课程的推进顺序，我大致分了四个阶段：

1. **信息的表示**：补码、浮点数（IEEE 754）、位运算技巧
2. **机器级表示**：x86-64 汇编、过程调用与栈帧
3. **链接与异常控制流**：符号解析、静态/动态链接、进程与信号
4. **存储器层次与虚拟内存**：Cache、页表、TLB、动态内存分配

## 一些印象深刻的细节

### 浮点数不是"精确"的

比如经典的比较：

```c
#include <stdio.h>

int main(void) {
    double x = 3.14;
    if (x * 100 == 314.0)       // 恒为假！
        printf("equal\n");
    else
        printf("not equal: %.17f\n", x * 100);
    return 0;
}
```

`3.14` 本身已经不能被二进制精确表示，乘法进一步引入误差。正确做法是用误差范围比较：`fabs(a - b) < eps`。

### Cache 容量与命中率

矩阵乘法的三重循环顺序，性能可以差数倍。以两种访问顺序为例，其命中率的差异可以用下面的模型估算——一个 $n \times n$ 的 double 矩阵，按行访问与按列访问对 Cache 行的利用率完全不同：

$$
\text{Cache 行利用率} = \frac{\text{实际复用的元素数}}{\text{加载的字节数} / 8}
$$

把 `k` 循环换到内层之后，我的实验耗时直接从 4.2s 降到 1.1s。
