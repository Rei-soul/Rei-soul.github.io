## 复现前的准备

我给自己定了三条规则：

1. 通读论文两遍：第一遍抓结构，第二遍逐个公式抄下来
2. 先跑通最小数据集，再上完整数据
3. 每实现一个模块，立刻用小规模输入验证形状和数值

## 从公式到模块

以注意力模块为例，论文中的定义为：

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

对应到 PyTorch 里，最朴素的实现是：

```python
import torch
import torch.nn.functional as F

def attention(q, k, v):
    # q: (B, H, N, dk)  k: (B, H, N, dk)  v: (B, H, N, dv)
    scores = torch.matmul(q, k.transpose(-2, -1)) / (q.size(-1) ** 0.5)
    attn = F.softmax(scores, dim=-1)
    return torch.matmul(attn, v), attn
```

实现完先不急着往下走，用随机张量验证三件事：

- 输出形状是否符合预期 $(B, H, N, d_v)$
- 每一行注意力权重是否求和为 1：`attn.sum(-1)` 全为 1
- 反向传播是否能回传梯度：`out.sum().backward()` 无报错

## 调试方法论

复现中最耗时的往往不是写代码，而是定位"结果不对"的原因。我的排查顺序：

### 1. 先怀疑数据

数据预处理是错误重灾区。归一化的均值方差、数据增强的顺序、标签的对应关系，每一项都值得打印出来肉眼检查。

### 2. 再怀疑超参

学习率过大时 loss 会先降后爆。记录每次实验的超参和曲线（哪怕失败的），失败实验的价值在于排除。

### 3. 最后怀疑实现

用极小规模的"手工数据"验证：比如自己构造 4 个样本，手算前向结果，和代码输出对比。
